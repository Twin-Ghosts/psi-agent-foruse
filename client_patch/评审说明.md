### 新文件

`_auth_manager.py`（`AuthManager`）— 登录态持有者 + 云端 aiohttp 客户端。
照 `_oauth_manager.py` 的形状写：dataclass + `anyio.Lock` + loguru + aiohttp。
**不持任何供应商密钥**；不注入 Session 构造参数、不写 ContextVar、不进
`_do_persist` 快照。

`_auth_store.py`（`AuthStore`）— 凭证落盘 `{appdata}/auth.enc.json` + `device_key` 持久化。
与 manager 分开是因为 keyring 是仓库里唯一一处平台相关代码，隔开便于在 CI
（无钥匙串）替换。

三点需要评审注意：

1. **凭证不进 `state/latest.json`。** 现有 `GatewayState.save` 把 AI 的 `api_key`
   明文写进快照；登录凭证走独立文件 + 钥匙串加密，不踩这个坑。
2. **钥匙串不可用时降级到明文，但打 warning 并在文件里标 `enc: false`**，不静默降级。
   保护边界是「操作系统用户」而非「进程」——同机恶意程序仍可以当前用户身份解密，
   这是桌面客户端固有限制。
3. **加密用异或 + 校验和，不是 AES。** 真正的秘密保护由操作系统钥匙串承担（密钥
   只在 Credential Manager / Keychain 里，磁盘上没有），异或只让磁盘文件不可直读。
   文件格式留了 `v` 字段，将来引入 cryptography 依赖可换 AES-GCM。
   **校验和是必需的**：异或没有完整性保证，换密钥只会解出乱码而不报错，
   没有校验和客户端会拿垃圾 token 请求、界面却一直显示「已登录」。

## 已知限制（方案文档已列，此处复述与本改动相关的）

- **本机 REST 无鉴权。** Gateway 绑 `127.0.0.1` + 随机端口但不校验凭证；
  浏览器中任意站点可向本地地址发请求。**本改动不加剧也不修复该风险**，
  需单独立项（本机 token + `Origin` / `Sec-Fetch-Site` 校验）。
- **离线不可登录**；已登录状态可离线使用（本机不主动回验 token）。
- **凭证泄露不可察觉**（无 refresh 轮换）。本期云端无高价值数据，做云端同步前必须补上。
