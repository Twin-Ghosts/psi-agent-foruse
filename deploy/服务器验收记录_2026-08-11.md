## 部署实况（与文档差异）

`deploy/验收清单.md` 假定的是本仓库 `psi-agent-auth` 的 `docker compose`（含独立 `backup` 服务、`/api/auth/otp` 路由）。服务器上实际运行的是**更新形态的 `psi-cloud`**，差异如下，验收命令已按实况调整：

- 项目根：`/srv/psi-cloud/`，compose 文件 `docker-compose.yml` 两个服务 `auth`(127.0.0.1:8081) + `analytics`(127.0.0.1:8082)。
- 镜像 `psi-cloud:latest`，入口 `uvicorn psi_cloud.auth.app:app --forwarded-allow-ips *`。
- 数据 bind mount：`/srv/psi-cloud/data/auth/auth.db → /data`。
- Caddy 是**系统级** `/etc/caddy/Caddyfile`（非 compose 内），`systemctl` 托管，active+enabled。
- 认证路由：`/otp` `/verify/email` `/verify/phone` `/complete` `/logout` `/me` `/sessions` `/healthz`（非文档的 `/api/auth/*`）。
- provider 当前 `sms=mock`、`email=mock`（真实凭据未启用）。

## 逐条明细

### 1. HTTPS 可访问 + 证书自动签发 — ⚠️ 部分通过

```
$ curl -sS -o /dev/null -w '%{http_code} ssl_verify=%{ssl_verify_result}\n' https://auth.example.com/healthz
200 ssl_verify=0                     # 证书链校验通过（未用 -k）

$ curl -sSI https://auth.example.com/healthz | grep -iE 'strict-transport|x-content-type|x-frame|referrer-policy'
Referrer-Policy: strict-origin-when-cross-origin
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
X-Frame-Options: DENY                 # 四条安全头齐全

$ curl -sS -o /dev/null -w '%{http_code} -> %{redirect_url}\n' http://auth.example.com/healthz
403 ->                               # 期望 308 -> https://...，实际 403 且无跳转
```

- ✅ 证书自动签发有效、证书链校验通过（`ssl_verify=0`）。
- ✅ 四条安全头齐全。
- ❌ **HTTP→HTTPS 跳转失败**。`/etc/caddy/Caddyfile` 里那个 `:80 { root * /usr/share/caddy; file_server }` 默认站块接管了对 80 端口按域名未匹配的请求，导致 `http://auth.example.com/healthz` 命中静态站而非跳 HTTPS，返回 403。参考 `deploy/Caddyfile.reference` 的设计是「80 自动 301→443」。**跟进**：为 80 端口的该域名显式配置 `redir https://{host}{uri}`，或把 vhost 的 `auth.example.com` 站块同时绑定到 80/443。

### 4. Caddy 透传真实客户端 IP — ✅ PASS

`send_quota` 桶因业务是脚手架（`/otp` 返回 501）无法落数，改用**应用访问日志中的客户端 IP** 作证据：

```
# 从本机公网向 https://.../otp 与 /healthz 发请求后：
docker logs psi-auth | tail
INFO: <客户端公网 IP>:0 - "POST /otp HTTP/1.1" 501 Not Implemented
INFO: <客户端公网 IP>:0 - "GET /healthz HTTP/1.1" 200 OK
INFO: 127.0.0.1:xxxxx - "GET /healthz ..."   # 这些是 Caddy 本机 healthcheck
```

uvicorn 以 `--forwarded-allow-ips *` 读取 `X-Forwarded-For`，日志记录的是**真实公网 IP `<客户端公网 IP>`**，而非 `172.x` 容器网段或 Caddy 的 `127.0.0.1`。透传链路成立，限频不会共用一个桶。

## 待跟进（部署缺口，非业务）

1. **HTTP→HTTPS 跳转（第 1 条）**：80 端口默认静态站块吞掉了域名请求，返回 403 而非 308。需在 Caddyfile 为该域名 80 端口加显式跳转。
2. **备份定时器未安装（第 5 条相关）**：`deploy/psi-cloud-backup.timer` / `.service` 单元文件已就位，但 `systemctl is-enabled psi-cloud-backup.timer` = `not-found`，未 `systemctl enable --now`。当前备份只能手动跑，每日 03:17 自动备份未生效。需 `cp deploy/psi-cloud-backup.* /etc/systemd/system/ && systemctl daemon-reload && systemctl enable --now psi-cloud-backup.timer`。
3. **业务逻辑脚手架（阻断真实链路验收）**：`/otp`、`/verify/email` 等发码/校验端点返回 501。文档验收清单第 5、6 步「真实收到邮件/短信」在业务实现补齐 + 真实凭据注入前无法验。当前 provider = mock。
