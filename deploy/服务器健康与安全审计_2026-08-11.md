## 5. 已执行的加固（2026-08-11 14:00 前后）

### S1 SSH 加固 — ✅ 已完成，双向验证

安全序列（全程有已验证退路，零锁死风险）：
1. 本机生成新密钥对 `~/.ssh/psi-cloud-root`（ed25519，私钥不离开本机）。
2. 公钥**追加**进 `/root/.ssh/authorized_keys`（原文件备份 `authorized_keys.bak-20260811`，此刻旧钥+新钥+密码三通）。
3. 用新私钥开独立连接实测登录成功 → 退路确认。
4. 发现密码登录实由 `/etc/ssh/sshd_config.d/50-cloud-init.conf` 的 `PasswordAuthentication yes` 覆盖开启（主 `sshd_config` 本是 no）。改该文件为 `no`（备份 `.bak-20260811`），`sshd -t` 通过，`systemctl reload ssh`。
5. **双向验证**：新密钥仍可登录（`KEY_STILL_OK`）；用正确密码经 paramiko 连接被拒（`PASSWORD_REJECTED`）。

结果：公网 SSH 现**仅接受密钥**，此前 25 次密码爆破尝试从此无效。
> ⚠️ 待你做：轮换 root 密码（当前密码仍在明文文档流通，虽已无法远程用于登录，仍建议改）。回滚：`cp /etc/ssh/sshd_config.d/50-cloud-init.conf.bak-20260811 …` 后 reload。

### S3 安全补丁 — ✅ 已装（未重启）

- `apt-get upgrade`（non-interactive，`--force-confold` 保留旧配置）装完 22 个安全更新（主要 systemd 系列），剩余安全更新 = 0。
- needrestart 列出若干延迟重启服务（含 docker），**均未逐个重启**（避免掐断容器）；容器显示「No containers need to be restarted」。
- **内核更新需重启才生效**（`/var/run/reboot-required` 存在）。重启未执行——有不可回归风险且你不在场。
> ⚠️ 待你做：择低峰期 `reboot`。容器 `restart=unless-stopped` + docker enabled，重启后自动恢复；建议你在场时做。

### S2 主机防火墙 — 未执行

Docker 会绕过 ufw 直接改 iptables，ufw 对已发布端口覆盖不完整，误配易断连、收益有限。当前依赖阿里云安全组（应确认只放行 22/80/443）。**维持现状**，除非你要纵深防御。

## 6. 升级后 443 公网访问异常 —— 已诊断，非服务器问题

打完补丁后公网 HTTPS 出现 `Connection reset`。**完整诊断结论：服务器侧 TLS 完全健康，与补丁无关，是阿里云 ICP 边缘拦截从 80 端口升级到了 443（SNI 层 RST 注入）。**

证据链：
| 测试 | 结果 | 含义 |
|---|---|---|
| 服务器自测 `https://本域名/healthz`（走公网回路） | 200 verify=0 | 服务器 443 健康 |
| 本机 `openssl s_client -servername 本域名` | CONNECTED，拿到真实证书 `CN=auth.example.com` | 从本机握手**能成功** |
| 本机 curl（schannel）本域名 SNI | 连续 Connection reset | 概率性 RST 注入 |
| TCP 直连 443 | OK | 传输层通，断在 TLS |
| caddy 日志 | 无 TLS 错误，正常记录请求 | 服务无异常 |

RST 是概率性的（openssl 抢到窗口连上，curl 连续被打断），与 80 端口备案拦截同一套 ICP 执法机制。**根治同样是完成 ICP 备案**（见 `ICP备案待办_2026-08-11.md`）。客户端 HTTPS 直连可能同样受概率性 RST 影响，进一步凸显备案的必要性。
