# 部署预检：本地实现版 → 上线替换 501 空壳

目的：把本地 `psi-agent-auth`（自检 23/23）部署上线，替换线上 `psi_cloud.auth`（全 501）。
预检发现 3 个必须先解决的对接问题，否则"直接部署"会 404 或构建失败。

## 本地版基线（已确认可用）

- 运行：`python -m app.server`，aiohttp + anyio，监听 `:8000`，`AUTH_DB=/data/auth.db`，非 root uid 10001。
- 结构：`app/{server,service,store,providers,real_providers}.py` + `contract/` + `schema.sql`。
- 自检：`verify.py` 23/23 全绿（含反向破坏点），实测非推断。

## 🔴 阻断点 1：Dockerfile 缺依赖，镜像跑不起来

`Dockerfile` 注释写"用标准库"，但 `server.py` 已改成 **aiohttp + anyio**，而：
- Dockerfile **没 `pip install aiohttp anyio`**
- 仓库根**没有 `requirements.txt`**

→ 现在 `docker build` 出来的镜像一跑就 `ModuleNotFoundError: aiohttp`。

**解法（🤖 我做）**：补 `requirements.txt`（aiohttp、anyio）+ 改 Dockerfile 装依赖。这是本地文件改动，无副作用。

## 🔴 阻断点 2：路由前缀三处口径不一致

| 位置 | 前缀 | 例 |
|---|---|---|
| 本地实现版（contract） | `/api/auth` | `/api/auth/otp` |
| 线上 psi_cloud 空壳 | 裸 | `/otp` |
| 线上 Caddy 反代 | `handle { → 8081 }` 把 `/` 全转 | 转给谁都行 |
| 客户端补丁（Gateway 本机） | `/auth/*` | 这是**客户端本机**前缀，非云端，不冲突 |

问题：Caddy 现在把 `/` 全量转 8081。换上本地版（`/api/auth/*`）后：
- 客户端请求 `/api/auth/otp` → Caddy 转 8081 → 本地版匹配 ✅
- 但线上现有约定和方案文档里，客户端到底打 `/otp` 还是 `/api/auth/otp`？**要和客户端补丁对齐**。

**解法（🤖 我做，需你无异议）**：以方案文档的 `/api/auth` 为准（契约就这么定的）。Caddy 反代不用改（它转 `/` 全量，带前缀也能匹配）。只需确认客户端补丁打的是 `/api/auth/*`——我在阶段5联调时核对。

## 🟡 阻断点 3：auth 与 analytics 共用镜像和 compose

线上 `psi-auth` 和 `psi-analytics` 都用 `image: psi-cloud:latest` + 同一 `docker-compose.yml`。
**analytics 是活的、在用**（真实写库），换 auth 绝不能碰它。

**解法（🤖 我做）**：本地版单独建镜像（如 `psi-auth-impl:latest`）+ 单独 compose 服务，只替换 `psi-auth` 容器，`psi-analytics` 完全不动。或用独立 compose 文件只管 auth。

## 建议的上线序列（真正动生产前会再确认）

1. 🤖 本地补 `requirements.txt` + 修 Dockerfile（无副作用，先做）。
2. 🤖 本地 `docker build` 验证镜像能构建、能起、mock 模式 `/api/auth/otp` 返回 200 而非 501（本机验，不碰生产）。
3. 🤖 把本地版代码 + 镜像推到服务器，建独立 auth 服务（不触 analytics）。
4. ⚠️ **切换那一下**：停旧 `psi-auth`(501) → 起新 auth(实现版)。会短暂停 auth（analytics 不受影响，线上无真实认证用户）。**这步我做前会明确告诉你。**
5. 🤖 复验：`/api/auth/otp` mock 走通发码→校验→建号→/me→踢设备全链路 + healthz。

## 依赖真凭据的部分（不在本次，等阶段2）

部署上线后仍是 mock provider。切真 provider 要等你给 Resend/PNVS 凭据（阶段2）。
即：**先把"实现版空跑通"上线，再接真凭据**，两件事解耦。
