# 部署验收清单

自检能覆盖配置内容、备份逻辑、生产默认值：

```bash
python 自检_部署.py            # 48 项
python 自检_部署.py --negative  # 9 个破坏点都要被抓到
```

**以下四条本地验不了，必须在服务器上验。** 自检不假装覆盖它们。

## 前置

```bash
# 1. DNS：auth.example.com 的 A 记录指向服务器公网 IP
dig +short auth.example.com

# 2. 80 与 443 必须可从公网访问（ACME HTTP-01 校验要用 80）
#    云厂商安全组与本机防火墙都要放行

# 3. 凭据写进 deploy/.env（该文件已被 .gitignore 排除，不要提交）
cat > deploy/.env <<'EOF'
ALIYUN_ACCESS_KEY_ID=...
ALIYUN_ACCESS_KEY_SECRET=...
DYPNS_SIGN_NAME=...
DYPNS_TEMPLATE_CODE=...
RESEND_API_KEY=...
RESEND_FROM=noreply@你的已验证域名
EMAIL_CODE_SALT=$(openssl rand -hex 32)
INVITATION_REQUIRED=false
EOF
chmod 600 deploy/.env
```

`EMAIL_CODE_SALT` 必须显式设置并**固定不变**：留空则每次重启换随机盐，重启前
发出的验证码全部失效。

## 1. HTTPS 可访问 + 证书自动签发

```bash
cd deploy && docker compose up -d
docker compose logs -f caddy      # 看 certificate obtained successfully

# 证书链有效（不带 -k，让它真的校验）
curl -sS -o /dev/null -w '%{http_code} %{ssl_verify_result}\n' \
  https://auth.example.com/healthz
# 期望：200 0        （ssl_verify_result=0 表示证书校验通过）

# 安全头齐全
curl -sSI https://auth.example.com/healthz | \
  grep -iE 'strict-transport|x-content-type|x-frame|referrer-policy'
# 期望：四条都在

# HTTP 自动跳 HTTPS
curl -sS -o /dev/null -w '%{http_code} -> %{redirect_url}\n' \
  http://auth.example.com/healthz
# 期望：308 -> https://...
```

## 2. 测试钩子不可从公网访问

```bash
curl -sS -o /dev/null -w '%{http_code}\n' \
  https://auth.example.com/__test__/provider_calls
# 期望：404。若返回 200，立刻停服 —— 该端点会回显验证码。
```

## 3. 重启不丢库

```bash
# 造一条数据（此处用邀请码表，不需要真发信）
docker compose exec auth python -c "
from app.store import Store
s = Store('/data/auth.db')
s.write(\"INSERT INTO invitation_codes(code, created_at) VALUES ('SMOKE-1', datetime('now'))\")
print('写入完成')"

# 完全重建容器（不是 restart，要验的是容器层数据不丢）
docker compose down && docker compose up -d
sleep 10

docker compose exec auth python -c "
from app.store import Store
s = Store('/data/auth.db')
print('SMOKE-1 是否还在:', s.one(\"SELECT code FROM invitation_codes WHERE code='SMOKE-1'\") is not None)"
# 期望：True
```

## 4. Caddy 透传真实客户端 IP

这条最容易被忽略，而且错了会**静默**削弱限频：所有用户共用一个桶。

```bash
# 从两台不同外网机器（或不同出口 IP）各发一次，第二台应当仍能成功。
# 若第二台就被 429，说明服务看到的是同一个 IP（Caddy 的地址）。
curl -sS -X POST https://auth.example.com/api/auth/otp \
  -H 'Content-Type: application/json' \
  -d '{"email":"probe1@example.com"}'
# 期望：{"retryAfter":60}

# 直接确认服务侧看到的地址
docker compose exec auth python -c "
from app.store import Store
s = Store('/data/auth.db')
print(s.all('SELECT scope, key FROM send_quota'))"
# 期望：scope='ip' 的 key 是真实公网 IP，不是 172.x 之类的容器网段地址
```

## 5. 备份真的可恢复

备份文件存在不等于可用。

```bash
docker compose logs backup | tail -5     # 看 integrity_check=ok

# 取一份备份出来，验证它能当库用
docker compose cp backup:/backups/. ./restore-test/
ls -1t restore-test/auth-*.db | head -1 | xargs -I{} python -c "
import sqlite3, sys
c = sqlite3.connect('{}')
print('integrity:', c.execute('PRAGMA integrity_check').fetchone()[0])
print('表数:', c.execute(\"SELECT COUNT(*) FROM sqlite_master WHERE type='table'\").fetchone()[0])
print('users:', c.execute('SELECT COUNT(*) FROM users').fetchone()[0])"
# 期望：integrity: ok，表数 7
```

## 已知限制

**单机即单点。** 挂掉则新用户无法注册、老用户 token 过期后无法续。C 端起步可
接受，但需配监控与快速重启。将来要高可用换 PG，数据模型不变。

**没接投递回执。** 邮件送达率无监控；短信有回执（HTTP 回调或 MNS 队列），首版
不接。用户报"收不到码"时目前只能查日志。
