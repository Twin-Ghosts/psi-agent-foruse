# 部署缺口修复（对应服务器验收记录的两条待跟进）

Kiro 在 2026-08-11 的服务器验收里,五条有 4 条 PASS,剩下两个缺口。这里给出可直接执行的修复。

**注意：服务器上跑的是 `psi-cloud`（FastAPI + systemd Caddy），不是本仓库的
`psi-agent-auth`（aiohttp + compose Caddy）。以下命令按服务器实况写。**

## 缺口 1：HTTP 80 端口返 403 —— **不是 Caddy 配置问题，改配置无用**

**现象**：`http://<域名>/healthz` 返回 403 且无跳转，期望 308。

**真实原因**：域名未在中国大陆完成 ICP 备案，请求在**到达 Caddy 之前**就被阿里云
边缘拦掉（返回备案拦截页）。实测：只要 HTTP 请求带该域名的 `Host` 头就 403，
裸 IP 无 Host 头返 200 —— 拦截发生在阿里云网络层，服务器上的 Caddy 根本没看到
这个请求。详见 `ICP备案待办_2026-08-11.md`。

> **本文档早先给出的修法（在 Caddyfile 里加 `redir`）是错的**，据此改配置不会有
> 任何效果，只会浪费时间并让人以为配置有问题。Caddy 侧的 80→443 跳转本来就已
> 就绪，备案生效后自动放行、无需再改。

**影响面（可能根本不用急）**：

- **客户端认证链路：无影响。** 客户端是 HTTPS 直连、不经浏览器跳转，443 一直正常。
- **浏览器手输域名：有影响。** 默认走 http 的人会看到备案页，不会自动跳 https。
- **将来官网 / 大陆 CDN 分发：有影响。** CDN 用大陆节点同样要备案。

**处置**：只做客户端 HTTPS 直连的话，备案可以延后，现状不阻断认证。要浏览器直达
或上大陆 CDN，则必须备案 —— 那一步涉及实名，只能你本人在阿里云控制台操作，
步骤见 `ICP备案待办_2026-08-11.md`。

**在此期间的兜底**：客户端固定使用 `https://` 前缀（当前实现就是这样，`endpoint`
配置里带 scheme），不依赖 80 端口跳转。这条已经成立，不需要额外改动。

## 缺口 2：备份定时器未启用（第 5 条相关）

**现象**：`systemctl is-enabled psi-cloud-backup.timer` = `not-found`。单元文件
已在 `deploy/` 下，但没装进 systemd，所以每日 03:17 的自动备份从未生效——
备份只在有人手动跑时才发生。

**为什么必须修**：验收第 5 条测的是"备份可恢复"，那次是手动触发的。定时器没启用
意味着**没有备份在自动产生**，真出事时最近的备份可能是几天前那次手工执行。

```bash
cp /srv/psi-cloud/deploy/psi-cloud-backup.service /etc/systemd/system/
cp /srv/psi-cloud/deploy/psi-cloud-backup.timer   /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now psi-cloud-backup.timer

# 验证
systemctl is-enabled psi-cloud-backup.timer    # 期望 enabled
systemctl list-timers psi-cloud-backup.timer   # 期望能看到 NEXT 时间
```

装完**不要只看 enabled 就算完**——立刻手动触发一次，确认服务单元本身能跑通：

```bash
systemctl start psi-cloud-backup.service
journalctl -u psi-cloud-backup.service -n 20 --no-pager
ls -lt /srv/psi-cloud/backups/ | head -3      # 应有新文件
```

## 附：本仓库版本的等价配置

若将来把服务器切成本仓库的 `psi-agent-auth`（compose 内置 Caddy），
这两条已经在配置里覆盖：

- 跳转：Caddy 对 `auth.example.com { ... }` 这种带域名的站块**自动**签证书并把
  80 重定向到 443，不需要手写 `redir`。当前服务器出问题是因为多了一个 `:80`
  默认站块把请求截走了。
- 备份定时：`docker-compose.yml` 里 `backup` 服务是常驻循环
  （`BACKUP_INTERVAL` 秒一轮），不依赖 systemd timer。

两种形态各自成立，别混用——混用就会出现"以为 compose 在备份、其实 systemd
timer 没装"这类缺口。
