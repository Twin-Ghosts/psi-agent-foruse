# 第三部分 · 第三轮修复（commit `9942a48`）：六套件 pytest 收集顺序无关（测试基建）

## 十、问题：测试套件对 pytest 收集顺序敏感

**现象**：六套件合并跑时，`_test_card_dsl_hardening.py` 4 项偶发失败（`KeyError: '_state'` / `KeyError: 'schema'`）；按字母序或单套件跑则全绿。

**根因**（三方 sys.modules 互扰，与产品代码无关）：

| 套件 | 行为 | 互扰 |
|---|---|---|
| strict（真实运行时） | collect 时 pop stub、重导真实 `_card_dsl`/`_todo_card_impl` | 若先于 stub 套件收集，真实 `_build_card_from_state` 被绑进 `_card_dsl`，stub 套件对 `_state` 形状的断言挂 |
| stub 套件（_test_card_dsl/fixes/spec） | `setdefault` 装 stub | setdefault 不覆盖已有模块，`_card_dsl` 绑定取决于「最后一次重导它的套件」 |
| hardening | `setdefault` 装 stub，断言依赖 `_state`/`schema` 形状 | strict 先收集时绑定真实版 → 4 项断言挂 |
| review_round | 直接覆盖 `sys.modules["_todo_card_impl"]` | 只 pop `_review_card_impl` 重导，不碰 `_card_dsl`（此前已修） |
| strict G03 | `_build_todo_card` 函数内延迟 `from _card_dsl import render_template` | 取 `sys.modules` **当前**版本：stub 套件后收集重导 stub 版 → G03 字节同构断言挂 |

## 十一、修复（三方隔离，任意顺序全绿）

| 套件 | 修复 |
|---|---|
| 4 个 stub 套件 | `setdefault` → **pop 后强制安装自身 stub + 重导 `_card_dsl`**：模块级绑定不再依赖收集顺序 |
| hardening | 改为**真实运行时**（strict 同款）：4 个依赖 stub 形状的断言改写为真实输出结构——done 行只读 = 零 handler（XSD 布尔漂移仍被钉住）；序列化不变量 = JSON 往返无损（覆盖普通卡 `schema` 与 todo 卡 `config/header/elements` 两种形状） |
| strict G03 | 测试内**临时钉住** `sys.modules["_card_dsl"]` 为真实模块，`finally` 恢复：任意顺序下 G03 都走真实模板 |

产品代码（`_card_dsl.py`/`_todo_card_impl.py`/`_review_card_impl.py`）**零改动**。
